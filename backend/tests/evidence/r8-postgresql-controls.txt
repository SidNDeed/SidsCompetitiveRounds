== why this report was produced more than once ==
The selection contains `test_the_committed_evidence_re_derives_its_own_numbers`
and `test_every_round_eight_control_names_a_test_that_exists`, so this file's
own subject includes the checks that read the evidence directory. Three times
in this round that has meant re-running rather than reasoning:

1. THE REPORT IS NOT WRITTEN INTO THE DIRECTORY IT MEASURES. The first attempt
   redirected the run's stdout INTO evidence/, so the evidence check read a
   file holding a header and nothing else and failed in both runs -- a run
   overlapping its own artifacts certifies nothing (#308). The report is now
   written outside the repository and moved in once the run has finished.

2. THE SELECTION'S OWN SOURCE CHANGED, SO THE RUN WAS REPEATED. Late in the
   round the evidence check's result pattern had to learn a new artifact type
   (the re-pin states its result as `rows rewritten now : 0`, which the
   round-7 pattern did not recognise, so the check reddened a report carrying
   exactly the result it exists to carry). That edit lands inside this
   selection. A report describing a selection whose source has since changed is
   a report about a tree nobody will commit, so it was re-run rather than
   re-labelled.

3. AND AGAIN, WHEN THAT REPAIR EXPOSED A LARGER ONE. The control added to
   prove the widening was named in none of the hand-written lists that pair
   controls to tests, and every one of those lists stayed green without it --
   a check that under-covers a set that grows. The repair derives the control
   set from the committed runner instead of restating it. It too lands inside
   this selection, so this report was produced a third time.

Of those three, the FIRST is the only run in the whole round that actually
failed, and it failed for the reason in item 1 rather than for anything about
the code under test. The second was green and was discarded because the tree
moved after it. The third is below.

== what the evidence directory held while this ran, stated exactly ==
Every r8 file existed, each holding its PREVIOUS attempt's contents: the
reports are written from their runs' stdout afterwards, so the directory this
selection read is not the directory committed at the end of the round. That is
a property of the whole round rather than a defect of this file, and it is why
no number in the round's notes is taken from a file in evidence/ -- every one
is quoted from the run's own output. What the evidence check verifies is a
STANDING property of the directory (each report carries a result, none cites a
path outside the repository), and that property holds for the committed set
too; the re-pin log records a final run of that check made against the
directory exactly as committed.

== THE PATHS ARE SANITISED BY THE INSTRUMENT, NOT BY AN EDITOR ==
pytest's header names the interpreter and the rootdir by absolute path, which
is this seat's checkout, and this file is committed. Round 7 deleted those two
lines from its transcript afterwards. A log edited to be true is a different
artifact from a log that was true when written, so the substitution is in the
script, anchored to the two line shapes that carry a path, keeping everything
else each line says: `platform ... -- <python>` and `rootdir: <repo>/backend`.
The rc printed after each run is pytest's own, read from PIPESTATUS -- `$?`
after a pipeline is the sanitiser's, and the sanitiser always succeeds.
