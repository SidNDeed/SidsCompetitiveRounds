The evidence assembler, run over this round's reports, 2026-09-21 (round 10)

The r6 lens raised this as a HIGH and as bar item B17: every report in this
directory CLAIMED to be generated from the stdout of the run it describes, and
nothing checked the claim. Round 9's suites report carried a file count its own
run never printed, in a sentence shaped exactly like the sentences around it
that WERE quoted, and nothing here could tell the two apart -- because nothing
compared a report against the bytes it came from.

`backend/tests/evidence/assemble-evidence.py` is that comparison, committed
rather than described. It does not transcribe and then hope: it REFUSES, exiting
non-zero and naming how many claims it could not derive, whenever a number in a
report's prose is absent from the stdout that report names.

== what counts as a claim, stated rather than left to taste ==
Two rules, complementary, neither catching what the other does:

  R1, the counting terms. An integer immediately followed by a term a run
      reports in -- passed, skipped, deselected, paths, controls, rows -- must
      appear in the stdout as the same integer next to the same term. This is
      the rule that catches round 9's defect, which was two digits wide and so
      invisible to any rule about big numbers.

  R2, the big numbers. Any integer of three digits or more that survives the
      typed exemptions must appear somewhere in the stdout. This is the rule
      that catches a summary total quoted with one digit changed, which R1
      would pass whenever the term beside it is right.

THE EXEMPTIONS ARE TYPED, NOT PER-NUMBER. A list of individually excused numbers
grows until the check cannot fail (#342), so what is exempt is a SHAPE -- a
numbered lesson, a date, a clock time, an evidence-file round tag, a bar or
finding row, a version or section number, a migration, an HTTP status, an
inclusive range. Adding a number to a report never silences the check; only
writing it in one of those shapes does, and each shape is something a run
genuinely does not print.

== both directions, on the rule rather than on this directory ==
The self-test below asserts that every matching rule FIRES and every exemption
STAYS QUIET, in both directions, so a typo in any pattern reds there rather than
passing for ever. Then the tool is run against each of this round's reports, and
then the refusal itself is executed on a fabricated pair: a narrative claiming a
count its stdout does not print is refused, and the refusal names the count. A
check that has only ever been seen to pass is a check nobody has seen work
(#391).

The same refusal is driven against the REAL report, not just a fabricated one,
by the mutation control `suites-report-carries-an-underived-number` in
r10-mutation-controls.txt: it puts into the suites report's prose a count no run
here can print, and requires the committed check to go red.

== this is not a step somebody remembers to take ==
The closing run below is the committed test pair -- `--selftest` plus a
re-check of every assembled report of the newest round -- so a report that
stopped matching its own stdout reds in the suite, not in a log nobody
re-reads. That is what makes the assembler a gate rather than a courtesy, and
it is the half of B17 the brief asked for by name.

== and it applies to itself ==
This file declares its own stdout and is assembled from it by the same tool, on
the rule this round adopted: once a round has one assembled report, every report
of that round is one. The check that reads this directory derives that set from
the files rather than from a list, so a round cannot adopt the rule for the file
that satisfies it and drop it for the file that would not.

The one file the rule cannot reach this way is the record of the re-pin, which
is written after every pytest run by construction. That report is produced by a
wrapper that applies these same rules -- imported from here, not restated -- to
its own text before writing it, and writes nothing if either refuses.
