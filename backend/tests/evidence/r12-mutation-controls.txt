A control here is a pair, never a single edit. The MUTATION breaks the property
and the paired test must go RED; the INERT twin changes the same site without
changing its meaning -- a comment, a reflow, a doubled space -- and the same
test must stay GREEN. Without the second half a red proves only that the test
noticed SOMETHING, which is not the same as noticing the thing (#391), and a
check that cannot fail is worse than no check at all (#342).

This file is ASSEMBLED by backend/tests/evidence/assemble-evidence.py from the
logs named above: everything below the marker is their exact bytes, and the
assembler refuses to write the file at all when a number in this narrative is
absent from them.

NO NORMALISATION IS APPLIED TO ANY OF THOSE LOGS. Each is the exact stdout of
the run that produced it, and each is LF because the instrument that wrote it
makes it LF.

ALL FOUR LOGS ARE WRITTEN OUTSIDE THE REPOSITORY AND COPIED IN, which is a
change of this round and follows from the other one. The evidence-log
re-inclusion in `.gitignore` used to be a blanket `*.log`; it is now one
pattern per producer, and either way a capture sitting in this directory is
UNTRACKED-AND-NOT-IGNORED -- the set the tree fence walks. A log written in
place is therefore the run detecting its own output, which is what the round's
discarded first pass demonstrated. The freeze guard has always been written
this way for the same reason, stated in its own header; this round the rest
joined it rather than being the exception.

== what the runner does, and what it refuses to do ==
It edits a file in place, runs ONE test, restores the file from a byte-exact
copy taken before anything ran, and repeats for the inert twin. Never
`git checkout --` and never `git restore`: both are forbidden on a tree
carrying uncommitted work (#290, #401), and this tree is carrying the round.
Before it runs anything it resolves every anchor in its target file and refuses
outright unless each resolves EXACTLY ONCE -- an anchor matching twice would
mutate two sites and an anchor matching zero times would mutate none, and both
look identical in a summary. At the end it compares the md5 of every file it
touched against the value taken before the first mutation, and says so per file.

== EVERY round's controls are re-run, not trusted ==
The inventory is 44 controls this round, and the count is the
runner's own: it prints the number it resolved anchors for before it runs
anything, and prints it again with the tally at the end. A count written here
by hand would be a number nobody checked.

Each round moves code around several of the previous rounds' anchors, and a
control that is not re-run on the tree it certifies is an assertion about a
different tree. So the inventory below is cumulative and all of it executes
here.

== THE CONTROL THAT CAME BACK GREEN, and what it changed ==
This is the round's own negative control doing the thing negative controls are
for, so it is recorded rather than smoothed. `producer-stops-naming-its-capture`
was run, its MUTANT deleted a producer's declaration of its own capture, and
the test STAYED GREEN. The derivation was a substring search for the capture
name across the instruments here -- and one instrument mentions every other
one's: this runner carries the producers' own lines as the anchors and mutants
of the controls that mutate them. So deleting a declaration left the derived
set unchanged, because the control's own anchor still said it, and a test that
cannot notice its own mutation is measuring something else (#342).

Two edits followed and both are in this round's diff. The derivation now
requires a capture declaration to OPEN its line -- bare, behind a comment
marker, or inside the `echo "` or `print("` that prints it -- so a name quoted
inside another statement is a MENTION and not a declaration. And the inert twin
changed with it: the twin used to be that line reflowed across two, which is no
longer inert, because splitting the line removes the name exactly as the mutant
does. A twin that reds is not a twin, so it is a doubled space at the same
site.

The suite pair that had already run against the tree before those two edits was
discarded rather than quoted. It was green; it was also about a tree that no
longer exists (#308). A third pair went the same way when the closing evidence
rule refused this round's assembly report -- its producer's log carried no
executed result -- and the fix for that is a closing check inside the producer.

== the freeze guard, and the older method beside it ==
The guard answers one question: did the tree move while the suite pair ran? A
guard that answers "no" for an edit class it cannot see is worse than no guard,
because the report then carries UNCHANGED over a tree the run did not have. So
its control performs each edit class and requires the guard to NOTICE, performs
no edit at all and requires it to stay quiet, and runs the earlier
captured-once method over the same two mutations side by side. That second half
is the negative result that makes the finding concrete rather than argued.

This round the guard also did its job on the round itself, outside its own
control: the first suite pair of the round redirected its captures into this
directory, the fence saw those files move under it, and the pair was discarded
rather than reported. An instrument that only ever agrees with its author is
not evidence.

== the citation pin ==
The contract states which revision of the client-lane method design its
realignment section was checked against; that document declares its own revision
on its first line. A citation is stale exactly when the two differ. The control
reds on a revision rolled back under the citation and stays green on a reword
beside it. It takes both paths as ARGUMENTS and names neither, because both live
under the gitignored scratch and a committed file may not send a reader to a
path this repository does not contain.

== the residual list's reach ==
A round's residual list is the one place it says what it did NOT close, and it
is read by somebody deliberately not reading the rest -- so it is the place a
summary sentence is most expensive to get wrong. `residual_rules.py` is the
rule: every item states its reach once in a pinned shape, the count under the
list is derived from those tags, and no other line in the section may state a
reach at all. `residual-reach-control.py` runs it against the real document --
passed as an ARGUMENT, for the same reason the citation pin takes its two --
with the superseded sentence put back as one mutation, a removed tag as a
second, and a reword beside a tag as the inert twin. The document is read and
never written; every edit is made to a copy in a temporary directory.
