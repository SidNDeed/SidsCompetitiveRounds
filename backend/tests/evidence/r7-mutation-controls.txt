Round 7's, and what each one is for:
  refund-statement-never-executed   read the RETURNING as a VALUE rather than
        as a row. Only a live server can tell those apart, and only on the
        refund that lands on exactly 0 -- which is why this control's test is
        one that RUNS the statement instead of asserting its text.
  refund-refusal-kills-the-queue    put the flush's refusal arm back to
        `break`, i.e. round 6's shape: one unpayable wager stops every other
        player's refund, permanently.
  refund-refusal-kills-the-sweep    put the prune's mode-2 call back to a bare
        _refund_series_bets: one unpayable series ends the whole pass.
  wager-lock-dropped-as-redundant   drop place_ffa_bet's own FOR NO KEY UPDATE
        on the lobby row -- the change the deleted comment would have
        licensed.
  relock-leaves-a-poisoned-transaction  drop the rollback from
        _ffa_progress_relocked's handler, so the fallback is returned into an
        aborted transaction and the next read answers bare.
  evidence-cites-a-gitignored-path  put a committed failure count back to a
        grep over a path this repository does not contain. It mutates the
        EVIDENCE, because the rule it guards is about the evidence; the
        forbidden path is ASSEMBLED in the runner rather than written out,
        since the rule applies to the runner too.
  refusal-skips-without-ending-the-transaction  drop the rollback from
        _refund_or_skip. The prune loops credit its skip as a way out of an
        iteration that has ENDED the transaction; this is what stops that
        credit becoming a hole. The only control whose test lives in another
        file (test_report_disconnect_durability.py, which owns the prune
        sweep's shape), which is why the runner takes a (file, name) pair.
