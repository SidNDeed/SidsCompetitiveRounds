Every mutation control, with its negative control, 2026-09-22 (round 11)
========================================================================

stdout: r11-mutation-run.log r11-freeze-guard.log r11-citation-pin.log r11-residual-reach.log

A control here is a pair, never a single edit. The MUTATION breaks the property
and the paired test must go RED; the INERT twin changes the same site without
changing its meaning -- a comment, a reflow, a doubled space -- and the same
test must stay GREEN. Without the second half a red proves only that the test
noticed SOMETHING, which is not the same as noticing the thing (#391), and a
check that cannot fail is worse than no check at all (#342).

This file is ASSEMBLED by backend/tests/evidence/assemble-evidence.py from the
logs named above: everything below the marker is their exact bytes, and the
assembler refuses to write the file at all when a number in this narrative is
absent from them.

NO NORMALISATION IS APPLIED TO ANY OF THOSE LOGS. Each is the exact stdout of
the run that produced it, and each is LF because the instrument that wrote it
makes it LF. That is a change this round made and it is not cosmetic: two of
these four instruments are Python, a Windows text stream writes CRLF, and a
report built from such a log would be LF above the marker and CRLF below. The
runner records a file's newline convention when it first reads it and writes
that one convention back, so a MIXED report comes back uniform, differs from
the bytes it started as, and is reported as not restored -- correctly, and for
a reason having nothing to do with the control being run. Round 10 reached the
same end by normalising at the copy step and recorded that as a deviation;
this round moved it into the instruments, so there is no step between a run
and the report that quotes it.

The freeze guard's log is the one written outside the repository and copied
in. That is not an exception to the rule above but a consequence of what the
guard measures: it fingerprints the whole working tree, so a log written in
place is the guard detecting its own output. The first attempt of this round
did exactly that and the guard refused, which is the instrument behaving as
its own header says it will.

== what the runner does, and what it refuses to do ==
It edits a file in place, runs ONE test, restores the file from a byte-exact
copy taken before anything ran, and repeats for the inert twin. Never
`git checkout --` and never `git restore`: both are forbidden on a tree
carrying uncommitted work (#290, #401), and this tree is carrying the round.
Before it runs anything it resolves every anchor in its target file and refuses
outright unless each resolves EXACTLY ONCE -- an anchor matching twice would
mutate two sites and an anchor matching zero times would mutate none, and both
look identical in a summary. At the end it compares the md5 of every file it
touched against the value taken before the first mutation, and says so per file.

== WHAT THE RUNNER NO LONGER HOLDS AS A LITERAL ==
Round 10 wrote `r10-suites.txt` into the runner as a path, with a comment
saying which round it belonged to. A path with a round number in it is a thing
to remember to bump, and a forgotten one makes this round's controls mutate the
PREVIOUS round's report -- a mutation that resolves, reds its test, and proves
nothing about the artifact this round is committing. The runner now DERIVES
both of the reports it mutates from the file names in this directory: the
newest suites report, and the newest mutation-controls report, which is
necessarily the previous round's because this round's is assembled from the
runner's own output and cannot exist while the runner runs. Both derived paths
are printed in the invocation block below, so the log says which files the
evidence-level controls ran against.

The same sweep found one more, inside this round's own new code -- which is
where the next false claim lives, because it is the code written by the hand
that had just finished making this argument everywhere else. The new-controls
control named TWO control names of one round as its anchor and its mutant,
written by hand, directly beside the derivations that had replaced the other
three. It fails in the conservative direction -- the anchor pre-check refuses
rather than passing -- so the cost is not a false green but a runner that will
not start until somebody carries two names forward by hand, which is precisely
the work this round exists to remove. Both names are now derived from the
target report and the module inventory, and the pair is printed in the
invocation block as `swap ... -> ... (derived)`.

== EVERY round's controls are re-run, not trusted ==
The inventory is 39 controls this round, and the count is the runner's own: it
prints the number it resolved anchors for before it runs anything, and prints
it again with the tally at the end. A count written here by hand would be a
number nobody checked -- which is exactly what the previous round's list of its
own new controls turned out to be, and is finding 4 of the r10 lens.

Each round moves code around several of the previous rounds' anchors, and a
control that is not re-run on the tree it certifies is an assertion about a
different tree. So the inventory below is cumulative and all of it executes
here. The rounds are deliberately not enumerated in the runner's header: an
enumeration of a growing set goes stale the round after it is written, which is
the defect this round is closing at three levels at once.

== this round's new controls ==
All six are at the level the r10 lens found -- the instruments and the
documents rather than the endpoint -- and four of the six mutate a RULE
rather than a document. That is deliberate. The directory as it stands
satisfies both the old reading of the scope and the new one, so a mutation of
the scope checked against the directory would prove nothing; what reds is the
rule's own fabricated fixture, which is where both directions live (#391).

  evidence-scope-keys-on-the-opt-in-set
      Restores the derivation the r10 lens found: the newest round taken over
      the reports that already DECLARE a stdout header rather than over every
      report's name. A later round that declared no header anywhere was then
      not the newest ADOPTING round, so none of its files were read and the
      rule was satisfied by a directory that had dropped it.

  scope-lets-a-report-belong-to-no-round
      The escape one spelling over, swept with it. The round is taken from the
      file NAME so that no report can opt out, which makes a name carrying no
      round an opt-out by unparseability. The mutant drops the clause that
      refuses one.

  selftest-count-is-not-derived
      Puts the assembler's printed check count back as the constant it was, on
      the one instrument here whose purpose is to refuse a number a run did not
      produce. Its inert twin is the SAME expression REFLOWED, which is the
      negative control that matters when the assertion is about a number: it
      must not be satisfiable by a line's shape (#441).

  new-controls-list-credits-another-round
      A report crediting its own round with a control another round added --
      the r10 defect, reproduced on the committed report. One listed name is
      swapped for a name the inventory tags for an earlier round, which reds in
      BOTH directions at once: one name listed and not tagged, one tagged and
      not listed. All three of its strings are DERIVED from the report and the
      inventory, so this control does not carry a round's names into the round
      after it. Its inert twin is the anchor with a trailing space -- still the
      same claim, which is what keeps the control about the NAME rather than
      about the shape of the line.

  residual-reach-rule-admits-a-prose-count
      Removes the clause that reds on a second statement of the reach, so the
      section is searched for the claim with every line taken out of it and the
      hand-counted summary the r10 lens found would pass.

  invocation-frame-drops-a-known-key
      The sibling of finding 2, one level down, and the one control this round
      added that no lens finding named. The invocation rule reads UPWARD from
      a result and stops at the first line it does not recognise, so its list
      of the frame keys a tool prints between a command and its output is a
      hand-written set beside a growing one -- the defect of the round,
      written into the rule that closes it. This round's runner prints two new
      frame lines, `reports` and `swap`. The mutant takes both keys back out
      of the list; the rule's own fabricated frame then reports a result whose
      command IS above it as carrying none. The negative twin lives inside
      that same self-test and is what makes the list load-bearing rather than
      decorative: a frame carrying a key the list has never been told about
      must still STOP the scan, or reading past the known frame would prove
      nothing about the list.

== the freeze guard, and round 8's method beside it ==
The guard answers one question: did the tree move while the suite pair ran? A
guard that answers "no" for an edit class it cannot see is worse than no guard,
because the report then carries UNCHANGED over a tree the run did not have. So
its control performs each edit class and requires the guard to NOTICE, performs
no edit at all and requires it to stay quiet, and runs ROUND 8'S captured-once
method over the same two mutations side by side. That second half is the
negative result that makes the finding concrete rather than argued.

== the citation pin ==
The contract states which revision of the client-lane method design its
realignment section was checked against; that document declares its own revision
on its first line. A citation is stale exactly when the two differ. The control
reds on a revision rolled back under the citation and stays green on a reword
beside it. It takes both paths as ARGUMENTS and names neither, because both live
under the gitignored scratch and a committed file may not send a reader to a
path this repository does not contain.

== the residual list's reach, new this round ==
A round's residual list is the one place it says what it did NOT close, and it
is read by somebody deliberately not reading the rest -- so it is the place a
summary sentence is most expensive to get wrong. The contract's list carried
two statements sixteen lines apart: an item saying two seats one number apart
can both settle, which is a second settlement of one physical game and pays it
twice, and a later item saying it was the only one in the list that could move
a rating. Neither sentence was wrong about its own subject. The second was a
count of the first, made once, by hand, and nothing in the document could
compare them (#351).

`residual_rules.py` is the rule: every item states its reach once in a pinned
shape, the count under the list is derived from those tags, and no other line
in the section may state a reach at all. That last clause is the one that reds
on the defect. `residual-reach-control.py` runs it against the real document --
passed as an ARGUMENT, for the same reason the citation pin takes its two --
with the superseded sentence put back as one mutation, a removed tag as a
second, and a reword beside a tag as the inert twin. The document is read and
never written; every edit is made to a copy in a temporary directory.
