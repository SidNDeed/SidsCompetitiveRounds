== THIS REPORT IS ITS OWN RUN'S OUTPUT, which is what round 10 changed here ==
The r6 lens found that round 9's report carried a count its run never printed,
in a sentence that looked exactly like every sentence around it that WAS
quoted -- and that nothing in this directory could tell the two apart, because
nothing compared a report against the bytes it came from.

So nothing compares them by hand now either. This file is ASSEMBLED by
backend/tests/evidence/assemble-evidence.py: the narrative above the marker is
written, everything below it is the exact bytes of the log named in the
`stdout:` header, and the assembler REFUSES to write the file at all when a
number in the narrative is absent from that log. Two rules decide what a
number is -- a count next to a term a run reports in, and any integer of three
digits or more that is not one of the typed exempt shapes -- and the
assembler's self-test asserts both fire and both stay quiet, so a typo in
either pattern reds rather than passing for ever.

The invocation of each half is printed by the script immediately before it
runs, and is in the verbatim block below rather than quoted up here. A report
that quotes its own commands twice has two places to keep true, and only one
of them is the one that ran.

ONE NORMALISATION IS APPLIED TO THE CAPTURE, and it is named here rather than
left to be discovered. The log below is this run's stdout with its line endings
written in the convention this directory uses throughout -- LF. Nothing else is
touched: no line is added, removed, reordered or reworded, and every byte that
carries meaning is the run's own.

It is not cosmetic. Two of the captured lines arrive as CRLF because they are
tailed from a pytest log that the interpreter wrote through a translating
stream, while the rest of the capture and every other file here is LF. A report
that mixed the two could not survive its own mutation control: the runner
records a file's newline convention when it first reads it and writes that one
convention back, so a mixed file would come back uniform, differ from the bytes
it started as, and be reported by the runner's md5 comparison as not restored --
correctly. The report has to be uniform for the control that mutates it to be
able to put it back.

The normalisation belongs in the instrument rather than in the copy step, and
it is not there yet: moving it would edit a file inside the fingerprint this
pair already printed, which would mean re-running the pair to buy it. It is
recorded as a deviation instead of being done quietly.

== THE FENCE, and the claim it is allowed to make ==
A suite that overlaps an edit to its own tree certifies nothing, and a sentence
saying it did not is a claim written from the one state its author had in mind.
So the tree is fingerprinted by backend/tests/evidence/tree-fingerprint.sh at
the start and again at the end, and the instrument RE-DERIVES its set at every
call: `git diff --name-only HEAD` for tracked files differing from HEAD, and
`git ls-files --others --exclude-standard` for files present but untracked. The
paths are part of the value, so an addition or a removal moves the fingerprint
even when every surviving file is untouched, and an unreadable path prints an
EMPTY hash rather than being skipped. The script refuses to run at all if the
fingerprint comes back empty.

Round 9's report said twelve paths were frozen and its run fingerprinted nine.
The correction is not a better sentence: the count is now PRINTED by the
instrument and QUOTED from the print, and the assembler refuses any other
number in its place. This round the instrument printed 11 paths, and the
closing UNCHANGED line below is the fence's verdict over the paths listed at the top --
this round's whole working set, source, tests, instruments, the ignore rule
that lets the captures be committed at all and the re-pinned route manifest
together, each byte-identical at the end to its hash at the start.

That guard is not an argument; it is run, with its negative control, in
r10-mutation-controls.txt: each edit class is PERFORMED and the guard is
required to notice, no edit at all is required to leave it quiet, and round 8's
captured-once method is run side by side over the same two mutations and
reports UNCHANGED for both.

Ignored paths stay out, by `--exclude-standard`. That is what lets this round
edit its own notes and its contract while the pair runs -- no suite reads them
-- and it is also why the per-half pytest logs go outside the repository.
Anything a run WRITES inside the repository and does not ignore moves this
value, correctly.

== what the numbers mean ==
The skip count in the opt-out summary IS a check, not a footnote: an opt-out
run that skipped as few as the live run did is a live run wearing the opt-out's
name. The two halves are two different questions, and `env -u` is what keeps
them that way.

== the difference between the halves, and it reconciles ==
The two summary lines are in the verbatim block below, each under the command
that produced it:

  opt-out   1737 passed, 44 skipped
  live DSN  1766 passed, 15 skipped

The live half runs the PostgreSQL-gated checks the opt-out half skips, so the
difference has to appear twice in the same two lines. It does: 44 - 15 is the
count of gated checks the live run executes, and 1766 - 1737 is the same count
read from the other column. Two numbers from two different columns of the same
two lines agreeing is the check; a disagreement there would be a finding, not a
rounding error.

Those four figures are the assembler's subject, not decoration. Each is a count
next to a term the run reports in, so each must appear in the log below as the
same integer beside the same term or this file does not get written -- which is
what the mutation control `suites-report-carries-an-underived-number`
demonstrates by putting a figure here that no run can print.

This round adds five tests: two live-gated and three not. A live-gated test
must move the opt-out's SKIP count and leave its PASSED count alone; an
ungated one must move the opt-out's PASSED count and leave its SKIP count
alone. Round 9's pair is committed beside this one in r9-suites.txt, and
against its two summary lines the arithmetic predicts exactly what the opt-out
line below printed -- three more passes and two more skips -- with the live
half's skip count unchanged. The prediction was written before the run was
read; that is what makes this a check rather than a description, and it is
also the positive signal that the gating is real rather than asserted.

No round-9 figure is quoted here, deliberately. Every number in this narrative
has to appear in the log below it or the assembler refuses to write the file,
and a number from a DIFFERENT run cannot. Where a comparison needs the other
round's figures, the other round's report is named instead of copied -- which
is the same rule one level up: a claim that cannot be traced to the artifact
under it does not belong in the artifact.

== failures in either run ==
Neither summary line above carries a `failed` term. pytest prints one whenever
a run has any, so its absence from a line quoted verbatim IS the zero, and it
is re-derivable from this file alone. Both halves also returned rc=0, printed
immediately above the line they describe.

Each summary line DOES carry an xfailed count -- a test marked
expected-to-fail, which did -- and that is not a failure count. The gate used
for these reports tests the TERM rather than the substring, and carries that
shape and its negative twin as assertions that run every time it is imported.
