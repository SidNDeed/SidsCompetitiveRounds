A control here is a pair, never a single edit. The MUTATION breaks the property
and the paired test must go RED; the INERT twin changes the same site without
changing its meaning -- a comment, a reflow, a doubled space -- and the same
test must stay GREEN. Without the second half a red proves only that the test
noticed SOMETHING, which is not the same as noticing the thing (#391), and a
check that cannot fail is worse than no check at all (#342).

logs named above: everything below the marker is their exact bytes, and the
assembler refuses to write the file at all when a number in this narrative is
absent from them.

== what the runner does, and what it refuses to do ==
It edits a file in place, runs ONE test, restores the file from a byte-exact
copy taken before anything ran, and repeats for the inert twin. Never
`git checkout --` and never `git restore`: both are forbidden on a tree
carrying uncommitted work (#290, #401), and this tree is carrying the round.
Before it runs anything it resolves every anchor in its target file and refuses
outright unless each resolves EXACTLY ONCE -- an anchor matching twice would
mutate two sites and an anchor matching zero times would mutate none, and both
look identical in a summary. At the end it compares the md5 of every file it
touched against the value taken before the first mutation, and says so per file.

== EVERY round's controls are re-run, not trusted ==
The count below is the runner's own: it prints the number it resolved anchors
for before it runs anything, and prints it again with the tally at the end. A
count written here by hand would be a number nobody checked.

== WHAT CHANGED IN THE SET THIS ROUND, and why a control was retired ==
The round implements a ruling: the arm that answers a report whose number the
lobby has already settled is TERMINAL for that entry. Rounds 12 and 13 had it
REDIRECT -- keep the entry, re-sign it once at the advertised number, submit --
and the redirect cannot be made safe, because the server cannot tell a behind
seat's LATER physical game from a CONFLICTING second account of the game
already settled at that number. They arrive as the same bytes under the same
key. Re-keying such a delivery at the free number settles the conflicting
account as a game of its own.

So one control is RETIRED and three are NEW, and two more survive with the leg
they redden moved rather than their mutation changed:

  terminal-walk-redirects-a-second-time  RETIRED. It mutated the BOUND on the
      redirect -- once per entry, terminal the second time. The ruling removes
      the redirect, so the rule it guarded is not on this tree, and a control
      that cannot be re-run on the tree it certifies is an assertion about a
      different tree. Its inventory entry stays, tagged RETIRED in place, so
      the evidence of the rounds that ran it still resolves. Its SITE is held
      by the first of the new controls below, whose mutation is the redirect
      happening at all.

  recovery-resubmits-the-stale-number  SURVIVES, expectation moved. The
      mutation is unchanged -- the advertised number is never written into the
      body -- and what it reddens is no longer the redirected entry's
      acceptance but the seat's NEXT game, which is keyed at the number it was
      just refused for and refused there.

  recovery-re-keys-the-parked-delivery and recovery-mints-a-second-parked-key
      SURVIVE unchanged. They hold the identity rule -- one entry per physical
      game, never moved, never duplicated -- which the ruling does not touch,
      and both still red on the key-set comparison the walk makes where the
      number is taken up.

round's claims was written down, and both were one defect in two places: a
control anchored on a quoted slice of PROSE that a later round is free to move.

The runner's underived-number control quoted a sentence out of the newest
suites report. The previous round reworded that sentence; nothing in that round
read it, because the controls run BEFORE the suite pair and a round's runner
therefore reads the PREVIOUS round's report; and this round's pre-check refused

is now the one line every assembled report is REQUIRED to carry -- the marker
that separates the narrative from the verbatim run, which the rules module
matches in every report it checks and which no round can reword without the
assembler refusing first. The mutation inserts a line above it, at the end of
the narrative, which is the region the assembler holds to its log; the inert
twin inserts a sentence at the same place with no figure in it.

The residual-reach control quoted a slice of one item's closing sentence, which
made it an anchor on the line BREAKS as much as on the words: this round
reflowed that paragraph without touching a claim inside it, and the control

structure and not its wording.

Neither re-pointing changes what is broken or where: the same property, the
same site, both halves executed below. What changed is that neither anchor is a
quotation any more.

== this round's new controls ==
Three in the runner, and in the standalone instrument a mutation reversed with
the disposition it checks plus a second pair beside it.

  terminal-arm-redirects-the-refused-entry
      Makes the disposition rule answer a settled-game refusal with a redirect,
      which is exactly what rounds 12 and 13 stated. The conflicting-account
      walk then re-signs that entry at the free number, the endpoint SETTLES
      it, and what reds is a SECOND row for one physical game -- a second
      rating and a second payout, which is the reason the arm is terminal. The
      redirect branch is written into the walk rather than omitted, so the
      mutation is EXECUTED instead of crashing three legs away (#391) -- and
      the walk reads the lobby's ROWS before it reads back the word the rule
      returned, which it did not do on this control's first run. It reddened
      then on the disposition string, three legs before the row, and a control
      that reports the first symptom it reaches is not a control over the one
      it exists for. The inert twin is a comment at the same site.

  terminal-walk-keeps-the-dropped-entry
      Makes the drop helper return a COPY of the entry instead of removing it,
      so the terminal disposition is announced and not taken. Every caller
      reads identically and the outbox still holds a delivery the server has
      already refused. What reds is the outbox, compared with the set captured
      before the drop rather than with a written-out pair. The inert twin is a
      comment at the same site.

  refusal-keeps-nothing-for-review
      Raises the contradiction refusal directly instead of through the capture
      helper. The ANSWER is byte-identical -- same status, same detail, same
      progress -- and nothing is kept. That is the whole cost of the terminal
      disposition: it is conservative only because the refused payload survives
      for an operator, so a game refused on this arm can be accepted by hand
      rather than lost. What reds is the quarantine record the walk reads back,
      not the response. The inert twin is a comment at the same site.

      inside the same cell, and the check stays CONSISTENT.

      The second mutation is new here and it exists to answer a carried

      the three places can now drift on its own and be caught on its own.

      The contract lives under the gitignored scratch, so the instrument takes

== the freeze guard, and the older method beside it ==
The guard answers one question: did the tree move while the suite pair ran? A
guard that answers "no" for an edit class it cannot see is worse than no guard,
because the report then carries UNCHANGED over a tree the run did not have. So
its control performs each edit class and requires the guard to NOTICE, performs
no edit at all and requires it to stay quiet, and runs the earlier
captured-once method over the same two mutations side by side.

== the citation pin ==
The contract states which revision of the client-lane method design its
realignment section was checked against; that document declares its own revision
on its first line. A citation is stale exactly when the two differ. The control
reds on a revision rolled back under the citation and stays green on a reword
beside it. It takes both paths as ARGUMENTS and names neither, because both live
under the gitignored scratch and a committed file may not send a reader to a
path this repository does not contain.

== the residual list's reach ==
A round's residual list is the one place it says what it did NOT close, and it
is read by somebody deliberately not reading the rest. `residual_rules.py` is
the rule: every item states its reach once in a pinned shape, the count under
the list is derived from those tags, and no other line in the section may state
a reach at all. This round ADDS an item to that list -- a genuine later game
refused at a settled number is not settled automatically -- so the tally under
it moves, and it moves because the tags moved rather than because anybody
counted. The control runs the rule against the real document, passed as an
ARGUMENT, with the superseded sentence put back as one mutation, a removed tag
as a second, and a reword beside a tag as the inert twin.

== the arm table's disposition ==
The instrument compares the two places the contract states one answer's
disposition: the arm table an implementer reads, and the recovery section the
server's behaviour is specified against. Nothing else reads them together, and
they said different things about one answer for a whole round once already.
This round REVERSES what it requires, because the ruling reverses the
disposition: the row must be TERMINAL for the entry, must say the entry is
dropped and that the server kept it, must NOT say REDIRECT, must name
`expected_game` as where the seat's next key comes from, and the recovery
section must state the same disposition in its own words. A document that
redirects is the finding the lens raised, and that is the first mutation.

It also reads a THIRD place this round -- the section that sorts answers into
terminal and retryable -- and carries a second mutation and a second inert twin
for it, because two statements compared and a third left loose is the same
defect the instrument was built for.
