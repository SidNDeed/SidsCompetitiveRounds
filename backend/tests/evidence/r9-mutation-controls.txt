Every mutation control, with its negative control, 2026-09-21 (round 9)
=======================================================================

A control here is a pair, never a single edit. The MUTATION breaks the property
and the paired test must go RED; the INERT twin changes the same site without
changing its meaning -- a comment, a doubled space -- and the same test must
stay GREEN. Without the second half a red proves only that the test noticed
SOMETHING, which is not the same as noticing the thing (#391), and a check that
cannot fail is worse than no check at all (#342).

All three are committed beside this report, and each of the three runs below is

mutation that reddened a check, with an inert twin that did not.

That was a decision with a cheaper-looking alternative, so it is recorded. The
check that reads this directory requires every report in it to carry an
executed result, and recognises one token per artifact type -- a pytest
summary, the migration's second run and its dump comparison, a mutation RED,
the re-pin's count. Neither new instrument prints one: the freeze guard says
`RED    class A` without the colon and the citation pin says `STALE`. The
alternatives were to widen that pattern a second time, or to edit the two
instruments to print a token they do not currently print. Widening makes a
check EASIER to satisfy, which is the direction that ends in a check that
cannot fail, and round 8 widened it once only because the check was refusing an
artifact that carried exactly the result it exists to carry -- not the case
here. Editing the instruments would have been fine in itself and was refused
for an unrelated reason: under this round's own stricter fence the instruments
are INSIDE the tree fingerprint, so editing one after the suite pair would
leave the committed bytes differing from the hashes that pair printed, and the
pair would have to be re-run to buy two characters. Filing them together costs
nothing and overstates nothing.

== what the runner does, and what it refuses to do ==
It edits a file in place, runs ONE test, restores the file from a byte-exact
copy taken before anything ran, and repeats for the inert twin. Never
`git checkout --` and never `git restore`: both are forbidden on a tree
carrying uncommitted work (#290, #401), and this tree is carrying the round.
Before it runs anything it resolves every anchor in its target file and refuses
outright unless each resolves EXACTLY ONCE -- an anchor matching twice would
mutate two sites and an anchor matching zero times would mutate none, and both
look identical in a summary. At the end it compares the md5 of every file it
touched against the value taken before the first mutation.

It also prints its own invocation immediately above the results, which is round
8's correction to round 7's log: fourteen RED lines and a tally, with no record
of what produced them, is a summary of a selection nobody can rebuild.

The earlier rounds' controls are RE-RUN rather than trusted. Each round's edits

re-run on the tree it certifies is an assertion about a different tree.

------------------------------------------------------------------------------
Finding 3's control. The guard under test answers one question: did the tree
move while the 23-minute suite pair ran? A guard that answers "no" for an edit
class it cannot see is worse than no guard, because the report then carries
UNCHANGED over a tree the run did not have.

So this does not ask whether the guard runs. It PERFORMS each edit class and
requires the guard to notice, and it performs no edit at all and requires the
guard to stay quiet:

  class A   a file CREATED during the run          must be detected
  class B   a tracked file that was byte-identical to HEAD, edited during the
            run                                    must be detected
  inert     no edit at all                         must NOT be detected

Round 8's own method is run SIDE BY SIDE over the same two mutations, and that
half is what makes the finding a result rather than an argument: the
captured-once list reports UNCHANGED for both, which is exactly what round 8's
committed `UNCHANGED: all 12 tracked files...` line was asserting.

It is the one instrument here that edits a TRACKED file, because class B is not
a class you can test by talking about it. The file is restored from a byte-exact

which are forbidden on a tree carrying uncommitted work (#290, #401) -- and the
control proves its own cleanup twice: the file's md5 against its pre-run value,
