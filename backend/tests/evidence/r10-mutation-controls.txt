A control here is a pair, never a single edit. The MUTATION breaks the property
and the paired test must go RED; the INERT twin changes the same site without
changing its meaning -- a comment, a reflow, a doubled space -- and the same
test must stay GREEN. Without the second half a red proves only that the test
noticed SOMETHING, which is not the same as noticing the thing (#391), and a
check that cannot fail is worse than no check at all (#342).

This file is ASSEMBLED by backend/tests/evidence/assemble-evidence.py from the
three logs named above: everything below the marker is their exact bytes, and
the assembler refuses to write the file at all when a number in this narrative
is absent from them. That is round 10's answer to the r6 HIGH on the evidence,
and it applies to this report exactly as it applies to the suites report.

== what the runner does, and what it refuses to do ==
It edits a file in place, runs ONE test, restores the file from a byte-exact
copy taken before anything ran, and repeats for the inert twin. Never
`git checkout --` and never `git restore`: both are forbidden on a tree
carrying uncommitted work (#290, #401), and this tree is carrying the round.
Before it runs anything it resolves every anchor in its target file and refuses
outright unless each resolves EXACTLY ONCE -- an anchor matching twice would
mutate two sites and an anchor matching zero times would mutate none, and both
look identical in a summary. At the end it compares the md5 of every file it
touched against the value taken before the first mutation, and says so per file.

That last line is not a formality this round. The session that began round 10
was interrupted between a mutant and its restore, and the file it was holding
kept the inert twin's comment until the next session found it by comparing the
tree against the fingerprint the suite pair had printed. The restore report and
the fence are what turn that from a silent carry into something a reader can
see, which is the whole argument for printing both.

== EVERY round's controls are re-run, not trusted ==
The inventory is 33 controls this round, and the count is the runner's own: it
prints the number it resolved anchors for before it runs anything, and prints
it again with the tally at the end. A count written here by hand would be a
number nobody checked.

Each round moves code around several of the previous rounds' anchors, and a
control that is not re-run on the tree it certifies is an assertion about a
different tree. So the inventory below is cumulative and all of it executes
here. The rounds are deliberately not enumerated in the runner's header: an
enumeration of a growing set goes stale the round after it is written, which is
the same defect this round closes twice elsewhere.

== this round's new controls ==
Two of them mutate the EVIDENCE rather than the source, which is the level the
r6 findings were at:

  evidence-results-without-an-invocation
      Drops one half's command line from the suites report, leaving a results
      block with no record of what produced it. Its inert twin is the same line
      with a space added, which is still a command line -- so what reds is the
      ABSENCE of the invocation and not the edit.

  suites-report-carries-an-underived-number
      Puts into the suites report's prose a count that no run here can print.
      This is round 9's finding itself, reproduced as an edit: the sentence
      looks exactly like the sentences around it that ARE quoted, and nothing
      before this round could tell the two apart.

The rest are at the two method changes:

  capture-refusal-restores-the-snapshot
      Catches the fail-closed refusal at the one place the caller's pre-capture
      copy is still in scope and answers from it -- literally the restoration
      of the snapshot the method change removed.

  double-failure-invents-a-progress
  vanished-lobby-invents-a-progress
      The two exhausted arms of the fresh read, one control each, because they
      are two reachable states and a control on one says nothing about the
      other. The mutants are the two inventions the old code made: the caller's
      stale copy, and `games_played = 0` for a lobby with no row at all.

  join-payload-omits-the-advertised-number
      Returns the settled count alone in the join-time payload, which is the
      shape that stood for five rounds. Under server allocation a seat may not
      derive the next number by adding one, so the payload has to carry it.

  acceptance-does-not-name-its-settled-game
      Drops `settled_game` from the accepted-report echo, so a client is left
      to infer settlement from the absence of a refusal. Its inert twin is the
      call REFLOWED across two lines, which is the negative control that
      matters here: the assertion is whitespace-flattened precisely so that it
      measures the call and not the line's shape.

  refusal-advertises-the-number-it-just-settled
      Makes a terminal refusal advertise the number it has just reported as
      settled. A seat deriving its key from the last advertisement would then
      key every later report at a number already taken and be refused for the
      same reason for ever -- the permanent exclusion the method change exists
      to remove.

== the freeze guard, and round 8's method beside it ==
The guard answers one question: did the tree move while the suite pair ran? A
guard that answers "no" for an edit class it cannot see is worse than no guard,
because the report then carries UNCHANGED over a tree the run did not have. So
its control performs each edit class and requires the guard to NOTICE, performs
no edit at all and requires it to stay quiet, and runs ROUND 8'S captured-once
method over the same two mutations side by side. That second half is the
negative result that makes the finding concrete rather than argued.

== the citation pin ==
The contract states which revision of the client-lane method design its
realignment section was checked against; that document declares its own revision
on its first line. A citation is stale exactly when the two differ. The control
reds on a revision rolled back under the citation and stays green on a reword
beside it. It takes both paths as ARGUMENTS and names neither, because both live
under the gitignored scratch and a committed file may not send a reader to a
path this repository does not contain.
