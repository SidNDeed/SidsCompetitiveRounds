== failures in either run ==
Neither summary line above carries a `failed` term. pytest prints one whenever
a run has any (#596: `N passed` is not a verdict, `failed` is), so its absence
from a line quoted verbatim IS the zero, and it is re-derivable from this file
alone rather than from a grep over a path this repository does not contain.
Both halves also returned rc=0, printed above the line they describe.

One precision, because the next reader will grep this file for the word. Each
summary line DOES carry the token `1 xfailed`, which is an expected failure --
one test marked as expected-to-fail, which did -- and is not a failure count.
pytest reports failures as `N failed`, a different term, and neither line
carries one. The distinction is not pedantic: this round's own assembler
tested the SUBSTRING `failed`, matched it inside `xfailed`, and refused to
write this report over a pair in which both halves were green. It now tests
the term. A filter that discards, or condemns, the very line it was built to
measure is the recurring shape (#441), and it is cheapest to catch in the
instrument that reads the line rather than in the prose that quotes it.

== why this is the round's THIRD pair, and the earlier two are not quoted ==
Two earlier pairs of this attempt ran GREEN and were discarded rather than
committed. Neither was discarded for a failure; both were discarded because a
source edit landed after them, and a pair that does not cover the final tree
certifies nothing.

  * After the first, the evidence check's result pattern still had to be
    widened. The re-pin states its result as `rows rewritten now : 0`, which
    the pattern did not recognise, so the check reddened a report carrying
    exactly the result it exists to carry.
  * After the second, that widening's own control exposed a larger version of
    the same defect. The checks pairing controls to tests were hand-written
    lists, so the newly added control was named in none of them and every one
    of them stayed green regardless. The repair derives the control set from
    the committed runner instead of restating it, and carries a control of its
    own.

Both repairs changed tracked files, so both cost a pair. The discarded pairs'
numbers appear nowhere in this round; only the run below is quoted.

== what the run certifies, exactly, and what it does not ==
TWELVE files -- every TRACKED file this branch's working copy changes -- were
md5'd by the script before the pair started and re-hashed when it finished,
and the script compared the two sets ITSELF. Its verdict, quoted:

  tree      12 tracked files differ from HEAD; hashed before and after
  UNCHANGED: all 12 tracked files are byte-identical to the pre-run hash

That comparison is the instrument's, not this report's. Round 7 asserted the
same property in prose, and a sentence saying a run did not overlap its own
tree is a claim written from the one state its author had in mind; a suite
that overlaps an edit to its own tree certifies nothing (#308), so the check
belongs in the thing that runs.

== what ran after this pair, and why that is still sound ==
THREE runs follow it: the PostgreSQL-gated selection, the mutation runner and
the route-manifest re-pin. None leaves the tree changed, and none is trusted
to say so in prose.

  * The PostgreSQL-gated selection only reads the tree and writes its report
    outside the repository, which is moved in when the run has finished.
  * The mutation runner mutates three files -- `backend/api/main.py`,
    `backend/tests/test_ffa_game_number_anchor.py`, and THIS REPORT, which one
    control targets -- and restores each from a byte-exact copy taken before it
    started, comparing md5 at the end and printing the comparison. It runs
    after this pair ON PURPOSE: that way the report it mutates as a control
    target is the one committed here, rather than a superseded attempt's.
    Round 8's first ordering ran it first and had to carry that mismatch as a
    stated limitation.
  * The re-pin runs WITHOUT `--write`, so it reports what a rewrite would
    change and changes nothing. `route_manifest_net_seat.json` is one of the
    twelve hashed above, and its hash is the same before this pair, after it,
    and at commit.
