== what counts as a claim, stated rather than left to taste ==
Two rules, complementary, neither catching what the other does:

  R1, the counting terms. An integer immediately followed by a term a run
      reports in -- passed, skipped, deselected, paths, controls, rows -- must
      appear in the stdout as the same integer next to the same term.

  R2, the big numbers. Any integer of three digits or more that survives the
      typed exemptions must appear somewhere in the stdout. This is the rule
      that catches a summary total quoted with one digit changed, which R1
      would pass whenever the term beside it is right.

THE EXEMPTIONS ARE TYPED, NOT PER-NUMBER. A list of individually excused numbers
grows until the check cannot fail (#342), so what is exempt is a SHAPE -- a
numbered lesson, a date, a clock time, an evidence-file round tag, a bar or
finding row, a version or section number, a migration, an HTTP status, an
inclusive range. Adding a number to a report never silences the check; only
writing it in one of those shapes does, and each shape is something a run
genuinely does not print.

== WHO THE RULE BINDS ==
The round is derived from the FILE NAMES, which no report can opt out of, and
every report of the newest round is bound: it names its stdout, it carries a
verbatim run section, and every result in that section has its command above
it. A report whose NAME carries no round is refused too -- that is the same
escape one spelling over.

Earlier rounds stay exempt, and for a reason that still holds: their reports
are the record of rounds already judged, on the shapes their instruments
printed at the time, and rewriting one now would be editing a log to satisfy a
rule written after it.

== both directions, on the rule rather than on this directory ==
The self-test below asserts that every matching rule FIRES and every exemption
STAYS QUIET, in both directions, so a typo in any pattern reds there rather than
passing for ever. Then the tool is run against each of this round's reports.
Then the refusal itself is EXECUTED on a fabricated pair -- a narrative claiming
a count its stdout does not print is refused, and the refusal names the count --
and the same rule is shown staying quiet on a claim the run did print. A check
that has only ever been seen to pass is a check nobody has seen work (#391).

The same refusal is driven against the REAL report by the mutation control
`suites-report-carries-an-underived-number` in r12-mutation-controls.txt: it
puts into the suites report's prose a count no run here can print, and requires
the committed check to go red.

== the producer RUNS the closing check, and that is how its absence was found ==
The rule that binds every report of a round asks two things of it: that its
verbatim run carries a command above every result, and that it carries an
EXECUTED result at all. This report's first draft satisfied the first and
failed the second -- its producer ran the assembler and printed its verdicts,
and not one line of the log was a result the rule recognises. The committed
check refused the file by name before it was ever committed, which is what a
closing check is for.

So the producer now ends by RUNNING that check: the assembler's self-test plus
a re-check of every assembled report of the newest round, under its own
invocation line, in the log below. The block is the last thing the producer
does, and its result is the last result in this file.

== and it applies to itself ==

is a report of the newest round, so the scope reaches it by its NAME, whatever
it declares.
