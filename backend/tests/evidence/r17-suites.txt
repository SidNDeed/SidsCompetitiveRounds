== THE FENCE, and what it holds this round ==
A suite that overlaps an edit to its own tree certifies nothing. So the tree
is fingerprinted by backend/tests/evidence/tree-fingerprint.sh at the start
and again at the end; the instrument re-derives its set at every call --
tracked files differing from HEAD, and files present but untracked -- and the
paths are part of the value, so an addition or a removal moves it even when
every surviving file is untouched. The script refuses to run at all when the
fingerprint comes back empty.

Every tracked change of this round -- the health marker, the re-pin of the
route manifest, and the negations that admit this round's captures -- was
COMMITTED before the pair, so no tracked file differs from HEAD. What the
fence lists is the one path this round produced before the pair: the capture
of the committed mutation runner's single run at this tip,
r17-mutation-run.log. That run refused at a gate in front of its anchor
pre-check, and the capture is its refusal in its own words: the runner derives the new-controls
control's swap from the newest mutation-controls report, and
r16-mutation-controls.txt lists no control as new in its round, so there was
nothing to take out of its list. It made no mutation and wrote no file. It
is committed with this report, unchanged.

Ignored paths stay out, by `--exclude-standard`, which is also why the
per-half pytest logs go outside the repository.

== what the numbers mean ==
The skip count in the opt-out summary IS a check, not a footnote: an opt-out
run that skipped as few as the live run did is a live run wearing the opt-out's
name. The two halves are two different questions, and `env -u` is what keeps
them that way.
