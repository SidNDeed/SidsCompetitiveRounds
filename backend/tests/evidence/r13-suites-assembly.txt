== THE LOG BELOW HAS A COMMITTED PRODUCER ==
Every number in every report here is derived from a committed instrument's
stdout, and this report says so about all of them -- so the log it is itself
assembled from has a committed producer too. A log with no producer is a log
whose blocks can drift without a diff: one could be dropped, re-ordered, or
re-run against a different report, and nothing in the repository would notice.

The producer is `backend/tests/evidence/run-assembly.sh`, committed beside this
file, and it was invoked exactly as its own header documents:

  bash backend/tests/evidence/run-assembly.sh > backend/tests/evidence/r13-suites-assembly-run.log

run from the repository root. The script prints that same capture name in its
own header line below, which is what pairs it with the evidence-log
re-inclusion in `.gitignore`. This round that pairing got its last pattern
taken out of it: the re-inclusion is now one exact NAME per capture per round,
so a file landing in this directory with a producer's suffix and a round
nobody ran is no longer admitted by the same line as the evidence.

THE ROUND IS DERIVED, never passed and never baked in. The script reads the
newest `r<N>-suites.txt` in this directory and takes its round from the name. A
round number written into a script is a thing to remember to bump, and a
forgotten one makes this round's run check the PREVIOUS round's reports and
report success -- the defect this directory has now closed four times over
(the suites path, the re-pin names, the suite tag, the new-controls anchors).
The set of reports it checks is derived the same way: every `r13-*.txt` in the
directory except the two that cannot be checked by a run that produces them.

== what counts as a claim, stated rather than left to taste ==
Two rules, complementary, neither catching what the other does:

  R1, the counting terms. An integer immediately followed by a term a run
      reports in -- passed, skipped, deselected, paths, controls, rows -- must
      appear in the stdout as the same integer next to the same term.

  R2, the big numbers. Any integer of three digits or more that survives the
      typed exemptions must appear somewhere in the stdout. This is the rule
      that catches a summary total quoted with one digit changed, which R1
      would pass whenever the term beside it is right.

THE EXEMPTIONS ARE TYPED, NOT PER-NUMBER. A list of individually excused numbers
grows until the check cannot fail (#342), so what is exempt is a SHAPE -- a
numbered lesson, a date, a clock time, an evidence-file round tag, a bar or
finding row, a version or section number, a migration, an HTTP status, an
inclusive range. Adding a number to a report never silences the check; only
writing it in one of those shapes does, and each shape is something a run
genuinely does not print.

== WHO THE RULE BINDS ==
The round is derived from the FILE NAMES, which no report can opt out of, and
every report of the newest round is bound: it names its stdout, it carries a
verbatim run section, and every result in that section has its command above
it. A report whose NAME carries no round is refused too -- that is the same
escape one spelling over.

Earlier rounds stay exempt, and for a reason that still holds: their reports
are the record of rounds already judged, on the shapes their instruments
printed at the time, and rewriting one now would be editing a log to satisfy a
rule written after it.

== both directions, on the rule rather than on this directory ==
The self-test below asserts that every matching rule FIRES and every exemption
STAYS QUIET, in both directions, so a typo in any pattern reds there rather than
passing for ever. Then the tool is run against each of this round's reports.
Then the refusal itself is EXECUTED on a fabricated pair -- a narrative claiming
a count its stdout does not print is refused, and the refusal names the count --
and the same rule is shown staying quiet on a claim the run did print. A check
that has only ever been seen to pass is a check nobody has seen work (#391).

The same refusal is driven against the REAL report by the mutation control
`suites-report-carries-an-underived-number` in r13-mutation-controls.txt: it
puts into the suites report's prose a count no run here can print, and requires
the committed check to go red.

== the producer RUNS the closing check ==
The rule that binds every report of a round asks two things of it: that its
verbatim run carries a command above every result, and that it carries an
EXECUTED result at all. A report whose run prints verdicts and not one line
the rule recognises as a result satisfies the first and fails the second, and
the committed check refuses it by name before it can be committed -- which is
how the absence of this block was found, in the round before this one.

So the producer ends by RUNNING that check: the assembler's self-test plus a
re-check of every assembled report of the newest round, under its own
invocation line, in the log below. The block is the last thing the producer
does, and its result is the last result in this file.

== and it applies to itself ==
This file declares its own stdout and is assembled from it by the same tool. It
is a report of the newest round, so the scope reaches it by its NAME, whatever
it declares.

The one file the rule cannot reach this way is the record of the re-pin, which
is written after every pytest run by construction. That report is produced by a
wrapper that applies these same rules -- imported from here, not restated -- to
its own text before writing it, and writes nothing if either refuses. This
round that wrapper stopped carrying one more thing nothing could check: the
attribution its two commits are made under is now DERIVED from the branch
rather than typed into the file, it refuses when nothing can be derived, and
before it writes anything it sweeps every message the final tip will carry for
any other claim of authorship, exempting exactly the line it derived.
